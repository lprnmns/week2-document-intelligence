# Local model compatibility

The model panel exists to make the local-first service operationally
understandable. It is not an Ollama dashboard or a guarantee that a model will
run.

## Collected system data

`HostProfileAdapter` collects only:

- operating system and CPU architecture;
- CPU model and logical/physical core counts when available;
- total/available RAM when the host exposes it;
- GPU presence, model, VRAM and fixed vendor acceleration probes;
- whether the process appears to be inside a container.

It does not expose usernames, home paths, arbitrary environment variables,
secrets, command output unrelated to model selection or raw `/proc` contents.
The API returns the sanitized `SystemProfile` projection.

## Runtime and roles

Ollama is reached through `OllamaModelRuntimeAdapter` using `/api/tags` and
`/api/pull`. The adapter never shells out. A pull accepts only identifiers from
the configured catalog (`DIS_OLLAMA_MODEL_CATALOG`) or the configured
generation model. Runtime availability and selected-model installation are
reported separately:

- `runtime_unavailable`: Ollama cannot be reached;
- `model_missing`: Ollama is reachable but the selected model is not installed;
- `ready`: runtime and selected generation model are both available.

The service keeps model roles separate:

- generation LLM: produces the grounded answer;
- dense embedding: creates index/query vectors;
- sparse/BM25: lexical retrieval implementation, not an LLM;
- reranker: bounded candidate reordering.

An Ollama model is not automatically considered a valid embedding or reranker
model. Unverified adapters are labelled as such.

## Estimation rules

The estimator is deterministic for a fixed `SystemProfile` and
`ModelMetadata`. It uses a conservative memory budget of approximately 65% of
total RAM. If GPU VRAM is available, 80% of reported VRAM can raise the budget,
but this does not promise a particular offload/runtime mode.

Estimated model memory is:

1. Ollama blob size × 1.15 plus a small context/KV allowance when blob size is
   known; or
2. parameter count × known quantization bits × 1.15 plus the same allowance
   when enough metadata exists.

The default context allowance is configured for 4096 tokens and scales
conservatively with `DIS_MODEL_CONTEXT_LENGTH`. It is deliberately
model-agnostic: the runtime may use a different KV layout, context length or
offload strategy, so the result remains a heuristic rather than a capacity
guarantee.

Missing size, parameter or quantization information returns:
`Resource estimate unavailable` and classification `unknown`.

The labels are intentionally probabilistic:

- `Recommended`: comfortable conservative headroom;
- `Likely usable`: likely fits with less headroom;
- `May run slowly`: may fit but latency/context pressure is plausible;
- `Memory risk`: close to or above the conservative budget;
- `Not recommended`: estimated footprint exceeds the budget;
- `Resource estimate unavailable`: insufficient metadata.

Quantization, context length, KV cache, runtime implementation, concurrent
requests and other processes can change the result. The UI must never replace
these labels with “will run”.

## Historical local-machine observation

The local smoke on 2026-08-10 reported Intel i7-1165G7, 4C/8T, 31.03 GB
RAM, no supported compute GPU, reachable Ollama and three installed runtime
models: `gemma3:4b`, `qwen3:4b` and `qwen3:4b-instruct-local`. The panel must
continue to distinguish both dimensions of status:

```text
INSTALLED / RECOMMENDED
INSTALLED / LIKELY USABLE
NOT INSTALLED / SLOW or RISK
UNKNOWN / RESOURCE ESTIMATE UNAVAILABLE
```

These are historical observations and heuristic labels for that host, not
current-machine readiness claims or hardcoded execution promises. The embedding
adapter and cross-encoder reranker remain
separate roles; the current reranker is not inferred to be an Ollama-installed
generation model.

## Embedding index safety

Changing the dense embedding model or output dimension is not a cosmetic model
selection. Existing Qdrant vectors were generated by a specific model and
collection dimension. The ingestion/query boundary must compare model identity,
dimension, collection schema and pipeline fingerprint before writing or
querying an index. An incompatible change requires deliberate re-indexing; it
must never silently query old vectors with a new model.

## Safe installation

Model management is disabled by default (`DIS_LOCAL_MODEL_MANAGEMENT_ENABLED=false`)
and intended for local development. When explicitly enabled, the UI sends a
validated model identifier to the runtime adapter and displays actual Ollama
progress. It cannot submit shell commands, URLs, arbitrary executable names or
unlisted model identifiers.
